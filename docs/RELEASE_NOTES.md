## Pixel-Pine-Launcher 0.1.4 预览版

这一版主要补 Android 端：它不再只是「能看市场」，而是能和桌面端配合着用——
同一套启停规则、同一套冲突判定、同格式的预设，以及应用内更新。

### Android

- **应用内更新**（设置 → 更新）
  - 读 GitHub Releases 的最新发布，逐段比较版本数字（`0.1.10 > 0.1.9`）
  - 下载 APK 到应用私有目录，经 `FileProvider` 交给系统安装器
  - 没有「安装未知应用」授权时跳转授权页并说明原因，不再点一下没反应
- **版本号修正**
  - `versionName` / `versionCode` 不再写死，构建时取自 `tauri.conf.json`，
    发版时以标签为准；设置页同时显示版本号与 versionCode
  - 之前写死 0.1.3，打新标签后包里仍是旧版本，应用内更新一比较就永远「已是最新」
- **库**
  - 扫描启用与停用两部分，开关即把 Mod 在 `units/` 与 `units/.disabled/` 之间移动
  - 同名单位目录的冲突会直接列出来（只算启用中的），和桌面端同一套判定
  - 卡片显示单位数、体积、修改时间
- **预设**（新页面）
  - 从当前库新建、应用、删除、导入 / 导出
  - 文件格式与桌面端 `Loadout` 一致，可跨设备搬运
  - Android 外置存储不支持符号链接，所以切换改的是启停状态：效果等价、可逆，
    Mod 文件一字节不动
- **市场**
  - 安装直接落到 `mods/units`，地图落到 `mods/maps`（zip 自动解开）
  - 带下载进度；不再只是把文件丢进系统下载目录
  - 目录没选对、没授权时明确报错，不静默失败

### 桌面端

- **扩展运行时清单**
  - 启动游戏前写 `<游戏>/ppl/runtime/plan.json`：加载顺序、入口类、mixin 与跳过原因
  - 缺依赖的扩展会从 entries 里剔除（界面仍会展示，方便排查）
  - 注入（JVM agent）仍未实现，游戏内暂不会生效——界面上也是这么写的

### 已知限制

- **Android 包是调试签名**，只用于预览；安装时需要允许「未知来源」
- Android 端不提供扩展管理与联机：前者依赖 JVM agent，后者依赖读游戏进程快照，
  两者在 Android 上都不成立，所以不摆空按钮
- 读 `mods/units` 在 Android 11 以上需要「所有文件访问」，首次进入库页会引导授权
- 扩展的注入部分仍未接入，目前只到「算好清单」这一步
